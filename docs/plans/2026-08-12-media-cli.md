# Media Library CLI — Implementation Plan (Plan 2A)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let someone add, scan and inspect a media library from a terminal, so adopting the feature never requires hand-editing `config.yaml`.

**Architecture:** A new `media` command in the existing CLI dispatch, with subcommands. It reuses `src/media/` wholesale — no new logic, only a terminal surface over what Plan 1 built — plus one config writer that follows the same rule `add_site` already follows.

**Tech Stack:** TypeScript (ESM, `node:` builtins only), `yaml` for the config write, `@clack/prompts` for interactive prompts, vitest.

**Source spec:** `docs/specs/2026-08-11-local-media-library-design.md`. Plan 1 (`docs/plans/2026-08-11-media-library-core.md`) shipped in 1.9.0 and listed this as its first named gap.

## Why this is first, ahead of the spec's own order

The spec put the CLI after fitting and enrichment. Real use on 2026-08-12 reversed that: drafting an actual article, the media library could not be used at all, because no library was configured and configuring one meant hand-editing `~/.byline/config.yaml` **and restarting the MCP server** — `loadContext()` reads config once at startup. The fallback was `upload_image` with a local path, which bypasses the library entirely.

A feature that cannot be adopted without a text editor and a restart is not adopted. That is what this plan fixes.

## Global Constraints

- **Node ≥ 20**, ESM, `.js` extensions on every relative import (plain `tsc`, no bundler).
- **`src/cli/` must gain no platform-, provider-, or library-specific branch.** The `media` command is a family-generic surface over `src/media/`; it must not name Ghost, WordPress, Gemini, or any specific library.
- **Byline never writes inside a user's library folder.** The CLI must not create, move, or delete anything under a library `path`.
- **Secrets never appear in `config.yaml`.** A media library has no secrets, but the writer must go through the same code path as `add_site` so this cannot drift — see Task 2.
- **Library names use `SLUG_PATTERN` imported from `src/config/sites.ts`.** Do not write a second regex.
- **`loadContext()` must never throw.** Nothing here may change that.
- **Nothing fails silently.** Every failure names the failing subsystem and carries a fix. The CLI's top-level error boundary must keep any command from showing a raw stack trace.
- **A destructive action requires explicit confirmation.** `--yes` semantics follow `reset`.
- Test files are NOT typechecked (`npm run typecheck` covers `src/**/*` only) — assert behaviour at runtime, no `as` casts to make a test compile.
- **Never write `process.env = { ...saved }`** in a test. Restore per key.
- No test deleted or weakened. The suite is at **1191 passing**; the floor is stated in `CLAUDE.md` in one place only.
- Run after every task: `npm run typecheck && npm test`.

## The MCP restart problem — read before Task 1

Adding a library to `config.yaml` does **not** make it visible to an already-running MCP server, because `loadContext()` runs once at startup. This plan does **not** attempt hot-reloading — that would mean re-resolving credentials, personas and provider chains mid-session, and every tool holding `ctx` would need to cope with it changing underneath.

Instead the CLI must **say so**. Every command that writes a library ends by telling the user, in plain words, that a running MCP server will not see it until the client is restarted. Silence here is the whole defect being fixed.

```ts
import { existsSync, readFileSync, statSync, writeFileSync } from 'node:fs';
import { parseDocument } from 'yaml';
import { SLUG_PATTERN, SLUG_RULE } from './sites.js';
import { ToolError } from '../errors.js';

export interface LibraryEntry {
  name: string;
  /** Absolute path, already expanded by the caller. */
  path: string;
  recursive?: boolean;
  indexPath?: string;
  setDefault?: boolean;
}

/**
 * The ONE writer of a `media.libraries` entry.
 *
 * Sibling of `site-block.ts`, and for the same reason: two hand-written copies
 * of "how a block gets written" is exactly how `init` and `add_site` drifted,
 * and that drift silently replaced a Ghost site with a WordPress one.
 *
 * Uses `parseDocument` rather than `parse` + re-serialise, so comments and key
 * order in a config the user has edited by hand survive the write.
 */
function loadDoc(configFile: string) {
  if (!existsSync(configFile)) {
    throw new ToolError({
      api: 'config',
      code: 'CONFIG_NOT_FOUND',
      message: `No config file at ${configFile}.`,
      hint: 'Run `byline init` first.',
    });
  }
  return parseDocument(readFileSync(configFile, 'utf8'));
}

export function addLibraryToConfig(
  configFile: string,
  entry: LibraryEntry,
): { written: boolean; warnings: string[] } {
  if (!SLUG_PATTERN.test(entry.name)) {
    throw new ToolError({
      api: 'config',
      code: 'BAD_LIBRARY_NAME',
      message: `"${entry.name}" is not a legal media library name. ${SLUG_RULE}`,
      hint: 'Pass --name with a different value.',
    });
  }
  if (!existsSync(entry.path)) {
    throw new ToolError({
      api: 'config',
      code: 'LIBRARY_PATH_MISSING',
      message: `${entry.path} does not exist.`,
      hint: 'Create the folder first, or point at one that already holds your photographs.',
    });
  }
  if (!statSync(entry.path).isDirectory()) {
    throw new ToolError({
      api: 'config',
      code: 'LIBRARY_PATH_NOT_DIR',
      message: `${entry.path} is not a directory.`,
      hint: 'A media library is a folder, not a single file.',
    });
  }

  const doc = loadDoc(configFile);
  const warnings: string[] = [];

  if (!doc.has('media')) doc.set('media', { libraries: [] });
  const media = doc.get('media') as { has(k: string): boolean; set(k: string, v: unknown): void; get(k: string): unknown };
  if (!media.has('libraries')) media.set('libraries', []);

  const libraries = media.get('libraries') as { toJSON(): Array<{ name: string }>; add(v: unknown): void };
  const existing = libraries.toJSON() ?? [];

  if (existing.some((l) => l?.name === entry.name)) {
    throw new ToolError({
      api: 'config',
      code: 'LIBRARY_EXISTS',
      message: `A media library named "${entry.name}" is already configured.`,
      hint: 'Pick another name, or run `byline media remove ' + entry.name + '` first.',
    });
  }

  libraries.add({
    name: entry.name,
    path: entry.path,
    ...(entry.recursive === false ? { recursive: false } : {}),
    ...(entry.indexPath ? { index_path: entry.indexPath } : {}),
  });

  // The first library becomes the default, because a user with exactly one
  // should never have to name it — and `getLibrary` already resolves a sole
  // library without a default, so this only makes the file say what is
  // already true.
  const isFirst = existing.length === 0;
  if (entry.setDefault || isFirst) {
    if (!media.has('default_library') || entry.setDefault) {
      media.set('default_library', entry.name);
      if (isFirst && !entry.setDefault) {
        warnings.push(`"${entry.name}" is now the default library.`);
      }
    }
  }

  writeFileSync(configFile, String(doc));
  return { written: true, warnings };
}

export function removeLibraryFromConfig(configFile: string, name: string): boolean {
  const doc = loadDoc(configFile);
  const media = doc.get('media') as { get(k: string): unknown; set(k: string, v: unknown): void; delete(k: string): void } | undefined;
  if (!media) return false;

  const librariesNode = media.get('libraries') as { toJSON(): Array<{ name: string }> } | undefined;
  const existing = librariesNode?.toJSON() ?? [];
  const kept = existing.filter((l) => l?.name !== name);
  if (kept.length === existing.length) return false;

  media.set('libraries', kept);
  if (media.get('default_library') === name) media.delete('default_library');

  // Only the config entry is removed. Nothing under the library `path` is
  // touched — byline never writes inside a user's library folder, and that
  // includes deleting it.
  writeFileSync(configFile, String(doc));
  return true;
}
```

## What this plan does NOT build

- **No hot reload.** A running MCP server still needs a restart; the CLI says so rather than pretending otherwise.
- **No enrichment, no fitting, no EXIF, no inspired-by, no brief `media` switch.** Those are Plan 2B.
- **No interactive wizard.** `byline media add <folder>` is one command; `init` is not extended in this plan.
- **No `find_media` staleness reporting.** Still deferred, still not shipped as a field hardcoded to `false`.
